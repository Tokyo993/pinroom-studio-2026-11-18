# PinStudio

Мобильное приложение по мотивам Pinterest со встроенной фотостудией. Пять экранов, реальный Wikimedia Commons API, личные коллекции, вход через ChatGPT и серверное хранение фотографий.

## Запуск на компьютере

Нужны **Node.js 24 LTS**, npm и интернет. API-ключ Wikimedia не требуется.

```sh
npm ci
npm run setup
npm run dev -- --port 4173
```

Откройте http://127.0.0.1:4173/. Команды выполняются из корня репозитория, где находится package.json. `setup` собирает Worker и применяет только ещё не выполненные миграции локальной базы. Повторный запуск безопасен для существующих данных. Для обычной работы после установки достаточно последней команды. Остановка — Ctrl+C.

Нажмите **Профиль → Войти через ChatGPT**. Только в локальном dev-режиме эта кнопка включает тестовый аккаунт **Seedy / seedy@sites.test**, без пароля и без обращения к настоящему ChatGPT. Это встроенная имитация для разработки, доступная на localhost. Локальные данные сохраняются в `.wrangler/state` и не загружаются на опубликованный сайт. Не публикуйте dev-сервер в интернет.

На опубликованном сайте действует настоящий вход через ChatGPT. Там нет общего тестового пароля. Проверяющий должен войти собственным разрешённым аккаунтом. Сейчас сайт и GitHub-репозиторий приватные; владелец должен предоставить проверяющему доступ перед отправкой.

- Репозиторий: https://github.com/Tokyo993/pinroom-studio-2026-11-18

## Проверки

```sh
npm run check
npm test
npm run build
```

`check` проверяет синтаксис; `test` запускает node:test, включая серверные проверки с SQLite и имитацией R2; `build` собирает production Worker. GitHub Actions повторяет эти проверки с Node.js 24 и `npm ci`.

Для браузерного прогона установите Google Chrome и необязательный Playwright:

```sh
npm install --no-save --package-lock=false playwright
node scripts/browser-check.mjs
```

Во втором терминале должен работать dev-сервер на 4173. `BASE_URL`, `BROWSER_EXECUTABLE`, `PLAYWRIGHT_MODULE` позволяют сменить адрес, браузер и модуль. Скрипт использует реальный внешний API; сетевые ограничения Wikimedia могут повлиять на результат. Отчёт сохраняется в `work/browser-report.json`.

## Пять экранов

| Экран | Маршрут | Сценарий |
| --- | --- | --- |
| Лента и поиск | `#/` | Категории, поиск, следующая порция результатов |
| Пин | `#/pin/:id` | Автор, лицензия, источник, сохранение, редактор |
| Коллекции | `#/boards` | Личные доски и создание новой |
| Коллекция | `#/board/:id` | Просмотр, переименование, удаление пина |
| Фотостудия | `#/edit/:id` | Кадрирование, настройки, фильтры, текст, PNG |

Вход, профиль и выбор коллекции — диалоги, не дополнительные страницы. Новая функция относительно выбранных базовых сценариев Pinterest — встроенный редактор с сохранением результата отдельным пином.

## Как проверить основной сценарий

1. Войти через профиль. Найти `mountains` или `cyberpunk city`.
2. Открыть пин и сохранить в новую коллекцию. Перезагрузить страницу и проверить сохранение.
3. Открыть фотостудию. Выбрать кадр 1:1, фильтр, добавить текст. Проверить отмену и повтор.
4. Скачать PNG и сохранить обработанную версию в коллекцию. Оригинал остаётся отдельным пином.
5. Загрузить своё JPG/PNG/WebP кнопкой «Создать», отредактировать и сохранить.
6. Выйти. Личные данные больше недоступны; повторный вход возвращает коллекции.

## Архитектура и защита

Клиент — HTML/CSS/JavaScript и Canvas. Vinext/Vite собирает сервер Cloudflare Worker. D1 хранит коллекции и метаданные файлов; R2 — сами приватные изображения. Сервер получает идентичность исключительно из доверенного Sites dispatch через `getChatGPTUser`. Передавать owner_id из браузера для выбора владельца запрещено.

Каждое чтение и изменение использует authenticated user ID. Изображения доступны только через защищённый `/api/assets/:id`, публичных R2-ссылок нет. Клиент связывает запросы с ожидаемым аккаунтом: при смене пользователя в другой вкладке сервер отклоняет старый запрос. Ревизии предотвращают незаметную перезапись данных при одновременном редактировании.

Изменения требуют точного совпадения Origin. Есть ограничения тела запроса, типов файлов и сигнатур, проверка ссылок и экранирование текста, CSP, `nosniff`, `no-store` для приватных ответов. Пароли и токены не хранятся приложением в localStorage. Точный механизм сессии и выход обслуживает платформа ChatGPT/Sites.

Старые коллекции IndexedDB не присваиваются аккаунту автоматически. Профиль предлагает явный импорт с подтверждением принадлежности и удалением локальной копии после успешного переноса.

## Исходники

- `client/shell.html` — оболочка и CSP
- `public/` — интерфейс, API-адаптер, Canvas, клиент серверного хранилища
- `app/` — серверная страница, API-маршрут, helper идентичности
- `server/account-api.mjs` — авторизация, валидация, D1/R2
- `db/schema.ts`, `drizzle/` — схема и миграции
- `tests/` — модульные и серверные интеграционные тесты
- `scripts/browser-check.mjs` — повторяемая браузерная проверка
- `docs/SUBMISSION.md` — описание для сдачи, ограничения и доказательства

`dist/` генерируется сборкой и не редактируется вручную. `npm run preview` запускает собранный Worker без локальной имитации входа; для интерактивной разработки используйте `npm run dev`.

## Публикация и ограничения

Проект настроен для Sites. `.openai/hosting.json` сохраняет существующий project_id и bindings DB/BUCKET. Публикация через Sites применяет серверные миграции отдельно от локальных. Не размещайте Worker напрямую на другом публичном адресе без собственной доверенной системы идентификации: helper ожидает проверенные заголовки платформы.

Лимиты: 100 коллекций, 1000 пинов, JSON до 1 МиБ, сохраняемый файл до 10 МиБ. Исходный файл редактора — до 15 МиБ; рабочая длинная сторона до 1600 px. Один текстовый слой, история до 40 состояний. Нет PSD, масок, кистей, совместных досок и рекомендаций на основе профиля. Удаление пина пока не очищает неиспользуемые R2-объекты; пользовательские квоты и автоматическая очистка не реализованы. При конфликте нужно обновить коллекции в профиле и повторить сохранение.

Это учебный проект, не официальный продукт Pinterest или Adobe. Лента поступает из Wikimedia Commons; авторство и лицензия сохраняются. Редактирование выполняется в браузере, а сохранённый результат отправляется в личное серверное хранилище. Поиск и IP-адрес видны Wikimedia.
